# NeuAI 集成 - 产品需求文档 (PRD)

## 项目概述

本项目旨在**新增** NeuAI 集成（基于 FlowiseAI）作为 Chatwoot 系统中的全新 AI 服务选项。**重要说明：不修改现有 OpenAI 集成的任何代码**，而是创建一个完全独立的新集成，让用户可以选择使用 OpenAI 或 NeuAI。

## 核心目标

1. **独立新增集成**：在保留 OpenAI 集成完整功能的基础上，新增 NeuAI 选项
2. **功能对等**：NeuAI 需实现 OpenAI 集成的所有 9 个核心功能
3. **配置灵活性**：支持按功能独立配置不同的 FlowiseAI agents
4. **用户可选**：用户可在设置中选择使用 OpenAI 或 NeuAI
5. **企业级扩展**：支持标签建议等企业版功能

## 功能需求

### 1. 消息级别功能（Message-Level Features）

需要完全实现以下 7 个功能：

- **rephrase** - 重新表述消息内容
- **fix_spelling_grammar** - 修正拼写和语法错误
- **shorten** - 缩短消息长度
- **expand** - 扩展消息内容
- **make_friendly** - 使语调更友好
- **make_formal** - 使语调更正式
- **simplify** - 简化表达方式

### 2. 对话级别功能（Conversation-Level Features）

需要实现以下核心功能：

- **reply_suggestion** - 生成智能回复建议
- **summarize** - 生成对话摘要
- **label_suggestion** - 智能标签推荐（企业版功能）

### 3. UI/UX 完全一致原则

**重要原则：前端 UI/UX 部分与 OpenAI integration 完全保持一致，可以直接拷贝现有代码**

- 保持现有的 AI Assist 按钮位置和交互方式
- 在对话输入框使用相同的触发机制
- 保持现有的弹窗展示模式
- 复用现有的组件样式和交互逻辑
- 用户界面无需区分使用的是 OpenAI 还是 NeuAI

## 技术架构

### 1. 集成配置结构

```yaml
neuai:
  id: neuai
  logo: neuai.png  # 使用占位符直到品牌资源就绪
  i18n_key: neuai
  action: /neuai
  hook_type: account
  allow_multiple_hooks: false
  settings_json_schema:
    type: 'object'
    properties:
      # 通用配置
      base_api_url: { type: 'string' }
      
      # 每个功能的独立配置
      reply_suggestion:
        type: 'object'
        properties:
          agent_id: { type: 'string' }
          api_key: { type: 'string' }
          api_url: { type: 'string' }
      
      summarize:
        type: 'object'
        properties:
          agent_id: { type: 'string' }
          api_key: { type: 'string' }
          api_url: { type: 'string' }
      
      # 其他功能配置...
      
      # 功能开关
      label_suggestion_enabled: { type: 'boolean' }
    required: ['base_api_url']
```

### 2. 后端服务架构

遵循现有的服务模式：

```
NeuAI 集成架构：
├── app/models/integrations/hook.rb (添加 neuai 处理)
├── app/services/integrations/
│   └── neuai/
│       ├── base_service.rb (基础服务类)
│       └── processor_service.rb (事件处理器)
├── lib/integrations/neuai/
│   ├── api_client.rb (FlowiseAI API 客户端)
│   └── prompts/ (提示词文件)
└── config/integration/apps.yml (集成配置)
```

### 3. API 调用模式

保持与 OpenAI 相同的后端代理模式：

```
Frontend → Backend API → NeuAI Service → FlowiseAI API → Backend → Frontend
```

### 4. FlowiseAI API 集成规范

**注意：可通过 context7 查询 FlowiseAI 官方文档获取最新 API 规范和使用指南。**

```ruby
# 标准 API 调用格式
{
  "question": "用户输入或对话历史",
  "overrideConfig": {
    "sessionId": "conversation_#{conversation_id}"
  }
}

# API 端点格式
POST https://flowise-api-url/api/v1/prediction/{agent_id}
Headers:
  - Authorization: Bearer {api_key}
  - Content-Type: application/json
```

## 实施计划

### 第一阶段：基础架构（1-2周）

1. **创建 NeuAI 集成配置**
   - 在 `config/integration/apps.yml` 添加独立的 neuai 配置
   - 不修改现有 openai 配置
   - 实现多功能独立配置支持
   - 添加 i18n 翻译（支持中英文）

2. **实现基础服务类**
   - 创建全新的 `Integrations::Neuai::BaseService`
   - 独立实现 FlowiseAI API 客户端
   - 添加错误处理和重试机制
   - 不依赖或修改 OpenAI 相关代码

3. **集成到现有钩子系统**
   - 在 `Integrations::Hook` 模型中添加 neuai 路由
   - 保持 openai 路由不变
   - 支持双集成并存

### 第二阶段：核心功能实现（2-3周）

4. **实现消息级别功能**
   - 开发 7 个消息处理功能
   - 创建对应的提示词模板
   - 添加单元测试

5. **实现对话级别功能**
   - 开发 reply_suggestion 功能
   - 开发 summarize 功能
   - 企业版：实现 label_suggestion

6. **前端集成**
   - **直接复用现有前端代码**：拷贝 OpenAI 相关的前端组件和逻辑
   - 创建新的 `useNeuAI` composable（基于现有 `useAI` 代码）
   - 添加 NeuAI API 客户端（基于现有 OpenAI API 客户端）
   - 在集成设置页面显示 OpenAI 和 NeuAI 两个选项
   - 用户可自由选择使用哪个 AI 服务
   - **UI/UX 完全一致**：用户无法从界面上区分使用的是哪个 AI 服务

### 第三阶段：测试与完善（1周）

7. **功能测试**
   - 完整的集成测试
   - 各功能的端到端测试
   - 错误场景测试

8. **用户体验完善**
   - 优化 AI 服务选择界面
   - 完善错误提示信息
   - 确保功能一致性

## 风险管理

### 技术风险

1. **API 兼容性**
   - 风险：FlowiseAI API 响应格式可能与 OpenAI 不同
   - 缓解：创建适配层统一响应格式

2. **性能差异**
   - 风险：FlowiseAI 响应时间可能不同
   - 缓解：实现超时控制和异步处理

3. **功能差异**
   - 风险：某些 OpenAI 特有功能可能难以复现
   - 缓解：通过精心设计的 FlowiseAI agents 来匹配功能

### 业务风险

1. **用户体验变化**
   - 风险：AI 响应质量可能有差异
   - 缓解：充分测试，收集用户反馈，持续优化

2. **迁移中断**
   - 风险：新增集成可能影响现有功能
   - 缓解：完全独立的代码路径，不触碰 OpenAI 代码

## 成功指标

1. **功能完整性**：100% 实现 OpenAI 的所有功能
2. **性能指标**：响应时间 < 3秒（P95）
3. **可用性**：服务可用性 > 99.9%
4. **用户满意度**：AI 建议采纳率保持或提升

## 依赖关系

1. **FlowiseAI 环境**
   - 需要部署和配置 FlowiseAI 实例
   - 为每个功能创建对应的 agents

2. **配置管理**
   - 需要安全存储多个 API keys
   - 支持环境变量配置

3. **监控系统**
   - 集成到现有的监控和告警系统
   - 添加 NeuAI 特定的指标

## 附录

### A. FlowiseAI Agent 配置示例

**重要：使用 context7 查询 FlowiseAI 官方文档以获取详细的配置指南和最佳实践。**

每个功能需要在 FlowiseAI 中创建独立的 agent，配置示例：

```
Reply Suggestion Agent:
- 模型：选择合适的 LLM（通过 context7 查询支持的模型列表）
- 系统提示词：参考 OpenAI reply.txt
- 温度：0.7
- 最大令牌：500

Summarize Agent:
- 模型：选择合适的 LLM
- 系统提示词：参考 OpenAI summary.txt
- 温度：0.3
- 最大令牌：300
```

### B. 配置优先级

1. 优先实现 reply_suggestion 和 summarize
2. 其次实现消息编辑功能
3. 最后实现企业版功能

### C. 集成共存策略

NeuAI 和 OpenAI 将作为两个独立的集成选项共存：
- 用户可在集成设置页面看到两个选项
- 可随时切换使用哪个 AI 服务
- 配置数据相互独立
- 不共享任何代码或配置

### D. 开发原则

1. **完全独立**：NeuAI 的所有代码都是新增的，不修改任何 OpenAI 相关代码
2. **功能对等**：确保 NeuAI 提供与 OpenAI 相同的功能体验
3. **文档驱动**：充分利用 context7 查询 FlowiseAI 文档
4. **前端复用**：直接拷贝 OpenAI 的前端代码，保持 UI/UX 完全一致
